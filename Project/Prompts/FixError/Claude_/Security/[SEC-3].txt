Phân tích và khắc phục lỗ hổng bảo mật `[SEC-03] Không có Rate Limiting thực sự` trong hệ thống NestJS microservices hiện tại.

Yêu cầu suy luận từng bước trước khi code:

1. Phân tích kiến trúc API Gateway hiện tại.
2. Xác định các endpoint có nguy cơ brute force hoặc spam cao.
3. Thiết kế giải pháp distributed rate limiting phù hợp cho production.
4. Đề xuất cấu hình limit hợp lý cho từng endpoint auth.
5. Refactor code theo clean architecture, tránh hard-code.

Thực hiện:

* Tích hợp `@nestjs/throttler`.
* Sử dụng Redis store để hỗ trợ multi-instance scaling.
* Áp dụng global throttling tại API Gateway.
* Thêm custom config riêng cho:

  * `/auth/login`
  * `/auth/register`
  * `/auth/forgot-password`
  * `/auth/verify-otp`
* Trả về HTTP 429 chuẩn hóa.
* Log các request bị block.
* Viết guard/middleware/interceptor cần thiết.
* Tạo `.env` config cho rate limiting.
* Đảm bảo hoạt động tốt với microservices architecture hiện tại.
* Sinh code hoàn chỉnh kèm giải thích ngắn cho từng phần quan trọng.
