Phân tích và khắc phục lỗ hổng bảo mật `[SEC-01] OTP Bị Lộ Trong API Response` trong hệ thống NestJS + NextJS hiện tại.

Bối cảnh:

* `users.controller.ts -> forgotPassword` đang trả về OTP trong response body.
* Frontend (`AuthSlidingForm.tsx`, `forgot-password/page.tsx`) còn render OTP lên UI.
* Có comment debug/demo bị sót trong production code.

Yêu cầu suy luận từng bước trước khi code:

1. Phân tích toàn bộ forgot-password flow hiện tại.
2. Xác định mọi vị trí OTP bị expose (API response, logs, frontend state, console, network response).
3. Đánh giá attack scenarios nếu attacker intercept response.
4. Thiết kế secure OTP flow theo production-ready standards.
5. Refactor để tách biệt rõ:

   * Development behavior
   * Production behavior

Thực hiện:

* Chỉ expose OTP khi `NODE_ENV !== 'production'`.
* Trong production:

  * Không trả OTP trong response.
  * Không render OTP trên frontend.
  * Chỉ gửi OTP qua email service.
* Loại bỏ toàn bộ debug/demo code liên quan OTP.
* Refactor forgot-password response DTO an toàn.
* Đảm bảo OTP không bị log ra console/server logs.
* Thêm env validation cho email/OTP configs.
* Chuẩn hóa success/error response tránh account enumeration.
* Kiểm tra lại frontend state management tránh lưu OTP ngoài cần thiết.
* Sinh code hoàn chỉnh cho backend + frontend.

Output:

1. Root cause analysis
2. Attack scenarios
3. Security flaws hiện tại
4. Thiết kế secure OTP flow
5. File structure thay đổi
6. Step-by-step refactor
7. Full code implementation
8. Security improvements đạt được
9. Remaining risks & hardening recommendations
10. Security verification checklist
