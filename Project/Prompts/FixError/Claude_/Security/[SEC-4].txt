Phân tích và khắc phục lỗ hổng bảo mật `[SEC-04] CORS Quá Rộng Trong Teamwork Service` trong hệ thống NestJS + NextJS microservices hiện tại.

Yêu cầu suy luận từng bước trước khi code:

1. Phân tích luồng WebSocket hiện tại giữa frontend, API Gateway và teamwork-service.
2. Xác định các điểm bypass authentication và authorization.
3. Đánh giá rủi ro khi client kết nối trực tiếp vào internal service.
4. Thiết kế kiến trúc WebSocket an toàn cho production.
5. Refactor theo clean architecture và centralized auth flow.

Thực hiện:

* Loại bỏ hardcoded `http://localhost:8006` trong frontend.
* Chuyển WebSocket connection đi qua API Gateway.
* Refactor websocket URL sử dụng env/config.
* Loại bỏ `origin: '*'` trong websocket CORS.
* Chỉ allow trusted frontend domains.
* Validate JWT token trong `handleConnection`.
* Tạo WebSocket auth guard/middleware dùng chung.
* Disconnect socket nếu token invalid/expired.
* Đồng bộ auth flow giữa HTTP và WebSocket.
* Đảm bảo teamwork-service không expose public internal port ngoài gateway.
* Sinh code hoàn chỉnh cho frontend + backend + gateway config.

Output:

1. Phân tích vấn đề
2. Kiến trúc hiện tại và rủi ro
3. Thiết kế giải pháp an toàn
4. File structure thay đổi
5. Code implementation hoàn chỉnh
6. WebSocket auth flow mới
7. Security improvements đạt được
8. Các rủi ro còn lại nếu chưa dùng WSS / reverse proxy / API Gateway websocket scaling
