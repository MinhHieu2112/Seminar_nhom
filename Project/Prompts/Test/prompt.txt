# Five S Prompt — Backend Testing Architecture

## 1. Simple
Sinh đầy đủ Unit Test, Integration Test và E2E Test cho backend hiện tại mà không thay đổi business logic.

## 2. Specific
- Unit Test:
  + Test từng service/function riêng lẻ
  + Mock repository, external API, database, socket, cache
  + Coverage cho success/failure/edge cases

- Integration Test:
  + Test flow giữa service + repository + database
  + Test authentication, authorization, transaction, validation

- E2E Test:
  + Test toàn bộ API flow thực tế
  + Test login, teamwork, task, upload file, notification, discussion realtime

## 3. Structured
Testing architecture:
- Co-location cho Unit/Integration Test:
  + Đặt file test cạnh service/module tương ứng
  + Ví dụ:
    src/modules/task/task.service.spec.ts
    src/modules/task/task.integration.spec.ts

- Centralized cho E2E:
  + Gom toàn bộ vào:
    /test/e2e
  + Ví dụ:
    test/e2e/auth.e2e-spec.ts
    test/e2e/task.e2e-spec.ts

Tech stack:
- Jest
- Supertest
- TestingModule
- Test database riêng
- Mock external services

## 4. Scalable
- Reusable test utilities
- Factory pattern cho seed data
- Global setup/teardown
- Test isolation
- CI/CD ready
- Dễ mở rộng khi thêm module mới

## 5. Safe
- Không sửa business logic hiện tại
- Không dùng production database
- Cleanup data sau mỗi test
- Tránh flaky test
- Validate coverage và stability trước khi hoàn thành
